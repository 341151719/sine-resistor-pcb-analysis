这是 PCB 修正、SPICE 分析和故障排查的审计仓库。仓库的目的，是让每次
电路修改、仿真假设和判断都能通过 Git 提交记录追溯；它不是已经通过生产
签核的最终硬件发布包。

## 当前诊断状态（2026-09-08）

官方 OPA548/OPA1656 模型在正确的 PSpice 兼容设置下可以运行。H12 进一步
解除此前“OPA548 固定 OFF”的假设，并加入 R10/TLP185、有限 E/S 状态和
J1/PGND 非理想项。23 组机制扫描没有自然产生 100--110 kHz；但当 OPA548
进入 ON 时，全官方模型出现约 453 kHz 的 U4B–R5–OPA548 组合模态，且把
R5 近似拆除后该模态消失。TP8 只有约 56 µVpp，因此仍不能解释实板上
100--110 kHz、超过 10 Vpp 的目标波形。H01–H11 的单点排查结论保持不变；
“本模型未复现”不等于已排除实物器件损坏、多故障叠加或未建模动态。

## 复现约定

仿真通常使用 ngspice-42；TI PSpice 宏模型需要 `set ngbehavior=ps`，并且
某些官方模型需要显式 `TEMP`。每个故障目录都记录了实际命令和模型限制。
历史网表中可能保留当时机器的绝对路径，这是审计记录的一部分；在新机器
上运行前应根据目录位置调整 `.include` 路径。`.dat` 波形文件和环境安装包
没有纳入 Git，它们可由网表重新生成，避免仓库膨胀。

## 版本纪律

V7 目录作为原始加工基线保留；V8 是当前修正版工作状态，不应在没有新的
验证记录时覆盖。请用独立提交记录新的板改动、仿真假设和结论，并在
`CHANGELOG.md` 中补充面向人的摘要。
