# 正弦电阻 V7 实验测试记录

## 一、记录目的

这份记录不再完整复述 KiCad 转换、PCB 文件分析、固件设计和 SPICE 环境配置，只整理项目中最有价值的实板测试过程。

核心问题最后集中为：

> 为什么在 OPA548 仍然关闭、J4 空载的情况下，TP7 基本正常，而 TP8/U4B 已经出现约 100～110 kHz 的大幅异常？

与这个问题直接相关的链路是：

`TP7(MUL_RAW) → U4B/OPA1656 → TP8(VCMD) → R5=100Ω → OPA548 +IN`

整个实验过程并不是一次找到根因，而是经历了多轮“测量—提出假设—重新测量—否定旧假设”的收敛过程。

---

## 二、第一轮：先确认 MCU、串口和 DAC 基础功能

最初测试没有直接开启功率级，而是采用分层上电方式。

第一阶段只开数字电源 J3，通过串口助手测试 STM32。V2 固件支持：

`PING / HELP / STATUS / READ ADC / STREAM / SET DAC1 / SET DAC2 / OPA ON / OPA OFF`

固件还有两个保护逻辑：

1. 修改 DAC 后会自动强制 `OPA OFF`；
2. `OPA ON` 后约 5 秒没有新的有效命令，会自动关闭 OPA。

串口通信、STREAM 和 FRAMES 都能正常工作。

随后测试 DAC1。发送不同 DAC 码：

`250 → 501 → 750`

示波器观察 TP6/VK，实际看到：

`负电压 → 接近0 → 正电压`

这个结果比较可靠，说明：

`STM32 → DAC1 → U8 → VK/TP6`

这一条控制链基本正常。

DAC2 通过 TP5 也可以观察到重复变化，但 TP5 并不是 DAC2 的直接输出，中间还有模拟注入网络和 U4A，因此这项只能说明 DAC2 控制有效，不能当作精密标定。

ADC/DMA 当时也持续运行，FRAMES 正常增长。但后来重新审计发现，最终 BOM 中几路主要 ADC 前端仍为 DNP，因此 `ADC=OK` 只能说明：

`TIM → ADC → DMA`

这条数字链在运行，并不能证明实际模拟反馈已经正确进入 MCU。

所以第一阶段之后，STM32、UART 和 DAC 基本被排除为后面 100 kHz 异常的直接信号源。

---

## 三、第二轮：发现 R10=100 kΩ 的 E/S 关断问题

随后开始测试 OPA548 的 Enable/Shutdown 支路。

原始设计中 R10=100 kΩ。实际逐渐升高 J1 电源时，在较低电压附近出现过突然增流，记录中大约在 ±2.5 V 左右开始异常。

为了判断是不是 OPA548 的 E/S 关断不可靠，在 R10 上并联 10 kΩ，使等效阻值约为：

`R10eq ≈ 9.1 kΩ`

改动之后测量：

`TP9 - TP14`

即 OPA548 E/S 相对负电源的电压，大约为：

`0.55～0.65 V`

关断状态明显变得稳定。

因此这一轮确认了一个真实设计问题：

`R10=100 kΩ`
→ 下拉能力太弱
→ OPA548 E/S 不能可靠贴近 V−
→ 有可能落入 E/S 未定义区或误开启。

但这里后来也修正了一个过度判断。

不能因为 9.1 kΩ 关断更可靠，就直接说最终 R10 一定要改成 4.7 kΩ 或 6.8 kΩ。R10 还必须满足光耦开启以后 OPA548 能可靠进入 ON，因此最终值必须同时验证：

`OFF 裕量`
和
`ON 裕量`

更重要的是，后面的测试表明：

**R10/E-S 问题和 105 kHz 不是同一个问题。**

R10 是原始 PCB 已经确认的独立风险，但不能单独解释 TP8 的 100～110 kHz 大振荡。

---

## 四、第三轮：OPA ON 后进入约 70 mA CC

基础控制链工作以后，开始执行：

`OPA ON`

实验现象很明确：

`OPA OFF`
→ 没有该异常 CC

`OPA ON`
→ 电流迅速上升，进入约 70 mA CC

约 5 秒没有新的有效命令：

`watchdog`
→ `OPA OFF`
→ 电流恢复

这个实验能够证明：

**异常耗流和 OPA Enable 状态之间存在明确因果关系。**

当时最自然的判断是：

- OPA548 自身自激；
- OPA548 损坏；
- OPA548 反馈或输出存在问题。

但这些判断后来被证明下得过早。

因为后面重新正确测量模拟前级时发现：

**OPA548 还没有 ON，TP8 就已经出现严重异常。**

因此现在回看这一轮，正确结论应该是：

> OPA ON 会使功率级进入异常耗流状态，但它并不能证明异常最早产生于 OPA548。

换句话说，当时观察到的 70 mA CC 后来逐渐从“根因”变成了“前级高频异常进入功率级后的结果”。

---

## 五、第四轮：一次必须作废的示波器测量

测试过程中曾经采用过这样的示波器连接：

`探头 tip → TP2`

`探头 GND 黑夹 → TP8`

接上以后观察到：

`J2 电流约20 mA → 70 mA`

同时出现异常波形。

早期讨论一度尝试从这些波形判断板子的故障。

后来重新审计后确认：

**这整轮数据必须作废。**

普通台式示波器的 GND 黑夹不是差分测量端，而是和保护地相连。

因此把黑夹接到 TP8，相当于：

`TP8 / U4B输出`
→ 被示波器强制接地。

TP8 又正好是 U4B 的 VCMD 输出。

所以这次测量真正做的是：

`强制拉低TP8`
→ `U4B输出级重载`
→ `J2电流增加`

而不是被动观察原来的电路状态。

因此“接探头以后 J2 从20 mA升到70 mA”不能作为 PCB 自身故障证据。

这里还必须区分实验记录中出现的两个“70 mA”：

第一种：

`OPA ON`
→ 功率电源进入约70 mA CC。

第二种：

`示波器错误把TP8接地`
→ J2 从约20 mA增加到约70 mA。

第二种是测量人为造成的。

以后记录电流时不能再只写“电源70 mA”，必须明确：

- J1 还是 J2；
- 正轨还是负轨；
- OPA ON/OFF 状态；
- 示波器怎么接。

---

## 六、第五轮：真正关键的发现——TP7干净，TP8出现100～110 kHz

修正示波器接法后，重新沿模拟链逐级测量。

这是整轮实验真正发生转折的地方。

在：

`OPA OFF`

的条件下发现：

`TP7 / MUL_RAW`
→ 基本干净

而：

`TP8 / VCMD`
→ 数伏级异常

后面进一步明确观察到：

`约100～110 kHz`
的大幅规则振荡。

这是目前最重要的实测证据。

因为：

`TP7 = U4B输入侧`

`TP8 = U4B输出`

所以异常第一次明显出现在：

`TP7 → U4B → TP8`

这一段。

这使以下部分作为 100 kHz 直接信号源的可能性明显下降：

- MCU；
- DAC；
- AD633 以前的数字控制；
- TP7 前级。

但当时也曾经出现一句稍微过强的判断：

> TP7干净、TP8振，所以一定就是U4B自己自激。

后来把它修正为：

> 异常发生在“U4B输出级及其所看到的负载系统”中。

因为 TP8 并不是一个完全孤立的节点，它继续通过：

`TP8`
→ `R5=100Ω`
→ `OPA548 +IN`

连接到 OPA548。

所以即使 OPA548 处于 OFF，其输入保护、shutdown 和内部结构仍然可能加载 TP8。

---

## 七、第六轮：改变 J1 后，TP8 波形发生状态变化

继续保持 OPA OFF，同时改变 OPA548 功率电源 J1。

观察到一个很有辨识度的现象。

J1 较低时，大约：

`J1 < ±6 V`

TP8 表现为比较规则的：

`100～110 kHz大幅振荡`

当 J1 提高到大约：

`±6 V附近及以上`

TP8 不再保持同样的规则波形，而逐渐变成另一种不规则纹波。

这说明：

**OPA548 即使处于 OFF，也并不是理想断路。**

J1 会改变 OPA548 输入保护、E/S/shutdown 或内部节点状态，并通过 R5 反过来影响 TP8。

但这个实验不能说明 OPA548 就是振荡起点。

因为在 J1 较低、OPA 仍 OFF 的时候：

`105 kHz已经存在`

所以到这一阶段，更合理的解释变成：

`U4B/TP8首先产生异常`
→ `R5把异常送到OPA548输入`
→ `J1改变OPA548 OFF内部状态`
→ `反过来改变TP8振荡形态`

因此 OPA548 更像“振荡状态改变器”，而不是已经证明的“105 kHz振荡发生器”。

---

## 八、第七轮：220 pF 可以压住异常，但不能叫根因修复

随后开始讨论并测试 U4B 反馈补偿。

在 R16=39 kΩ 上并联 220 pF，其 RC 极点约：

`18.5 kHz`

所以对 100～110 kHz 来说，这是一个非常强的高频反馈改变。

实板讨论和后续仿真都表明：

增加几十到几百 pF 后，100 kHz 异常可以明显降低甚至消失。

因此 220 pF 非常适合做一个判别实验：

> 如果改变 U4B 高频反馈以后，100 kHz 发生巨大变化，说明异常确实高度依赖 U4B 高频闭环状态。

但后来明确不能再写：

> 缺少220 pF就是根因。

因为同步当前实板参数后的健康 OPA1656 模型，在：

`Cfb=0`

时本身就有约：

`PM≈62°`

也就是说正常 `OPA1656 + 1k/39k` 并不是一个天然应该自激的设计。

220 pF 真正做的是：

**强烈降低 100 kHz 附近的闭环传递增益。**

所以它可以“压住症状”，不代表找到了症状为什么产生。

另外项目最终还要实现约 10～1000 Hz 的动态阻抗调制。补偿过大虽然稳定，却会损失动态跟踪性能。

因此后来建议真正要扫的是：

`0 / 22 / 47 / 100 / 220 pF`

而不是直接把 220 pF 焊上以后宣布问题解决。

220 pF 的最终定位变成：

**诊断/抑制措施，而不是已证明的根因修复。**

---

## 九、第八轮：pin6“高阻虚焊”曾经很像根因，但被实测推翻

在观察到：

`TP8大幅105kHz`

同时：

`U4B_N也能看到同频信号`

以后，曾经提出一个很有迷惑性的假设：

R15/R16 分压节点本身可能正常，但反馈并没有真正进入 OPA1656 pin6。

也就是说可能存在：

`R15/R16节点`
→ `高阻/虚焊`
→ `U4 pin6`

如果 pin6 没有真正接入，那么 U4B 可能近似失去负反馈。

这个假设在局部 SPICE 中甚至可以通过 MΩ 级连接异常，把系统拟合到约100～110 kHz。

一度看起来非常像。

随后做了最直接的断电测量：

`U4 pin6金属脚 ↔ U4B_N`
≈ `20 mΩ`

而且：

**完全没有上过电的新板也是约20 mΩ。**

这个实测直接否定了：

`外部pin6存在1.6～2 MΩ高阻虚焊`

这一类根因模型。

这也是整个项目排查中很重要的一次经验：

> SPICE 能拟合出故障，不等于故障真的存在。

只要直接实测与模型矛盾，就必须放弃这个模型，不能因为它“频率刚好105 kHz”而继续保留。

从这一轮开始，问题从“单块板焊接异常”转向：

- 所有同版 PCB 共有的问题；
- U4 器件本体状态；
- PCB 模型没有覆盖的动态；
- OPA548 OFF 的真实内部机制。

---

## 十、第九轮：正常 U4B 和普通 PCB 寄生都解释不了105 kHz

同步实板参数后，U4B 局部 SPICE 使用：

`R15=1k`
`R16=39k`
`R5=100Ω`
`健康OPA1656`

得到 nominal 环路：

`fc≈1.14 MHz`

`PM≈62°`

普通探头负载以及常见寄生都无法让它在100～110 kHz自激。

后面进一步构造 PCB-aware 模型，把：

- U4 供电走线；
- 远端去耦；
- U4A/U4B共电源；
- AD633输出阻抗；
- VCMD/U4B_N走线；
- AGND/PGND一阶寄生；
- OPA548 OFF输入负载；

逐步加入。

健康模型仍然大约：

`PM≈63～64°`

没有产生实板的105 kHz。

继续做 fault matrix 后，以下方向也明显降级：

- 合理范围的 `VCMD → U4B +IN` 互电容；
- R15 局部 ground bounce；
- 普通 R15/R16/R5 错值；
- OPA548 OFF 的普通 pF/MΩ 被动耦合；
- J4 OPEN 时完整 INA149→U4A→AD633 全局反馈。

换句话说，实验和仿真共同说明：

> 真正缺失的机制不是简单“多了几pF、几十nH”。

健康模型在105 kHz附近还需要非常强的额外幅相变化才能失稳，因此后面的关注点逐渐转向：

- U4 实际器件状态与健康 OPA1656 不一致；
- 错型号、异常批次或器件损伤；
- OPA548 shutdown 的真实非线性；
- 当前模型没有表达的更强状态机制。

---

## 十一、现在怎样理解 OPA ON 后的 70 mA CC

到实验后期，`OPA ON → 70mA CC` 已经不再是最大的谜题。

当前最合理的事件顺序是：

`OPA OFF`
→ `TP7基本干净`
→ `TP8已经出现约105kHz大幅异常`

然后：

`OPA ON`
→ `OPA548开始处理异常TP8`
→ `输出产生100kHz高频`
→ `4.7Ω + 47nF snubber产生明显高频电流`
→ `即使J4 OPEN，也可能出现较大功率级耗流`
→ `J1进入约70mA CC`

因此：

> OPA ON 后 CC 更像 105 kHz 前级异常的后果，不是105 kHz最初产生的原因。

这也是为什么后续测试105 kHz时，应首先保持：

`OPA OFF`

而不是一开始就开启功率级。

---

## 十二、当前实验结论

截至现有对话记录，可以比较确定地保留下列结论。

第一，STM32、UART、DAC1、DAC2 基础功能基本正常，目前没有证据说明 105 kHz 是 MCU 或 DAC 产生的。

第二，R10=100 kΩ 的 OPA548 E/S 关断设计存在真实风险，并联10 kΩ后 OFF 状态明显改善。但它是一个独立问题，不能和105 kHz合并。

第三，曾经把示波器 GND 接到 TP8 的实验属于人为改变电路，那一轮 J2 增流和对应波形必须作废。

第四，最重要的实测事实是：

`OPA OFF`
`TP7基本干净`
`TP8≈100～110kHz大幅异常`

因此异常区域已经被压缩到：

`U4B / 反馈网络 / TP8后级加载`

而不是整块系统。

第五，J1 大约 ±6 V 附近能够改变 TP8 波形，说明 OPA548 OFF 状态确实参与系统动态，但目前没有证明它是最初105 kHz的发生器。

第六，220 pF 能强烈抑制异常，但只能作为诊断和临时稳定手段，不能作为根因已经找到的证据。

第七，U4 pin6 外部 MΩ 级虚焊已经被约20 mΩ的直接测量否定。

第八，正常 OPA1656 + 1k/39k 以及目前已经建模的普通 PCB 寄生都不能自然产生实板105 kHz。

因此现在真正没有完成的只剩一个核心问题：

> **为什么真实 U4B/TP8 的动态行为与健康 OPA1656 + PCB-aware 模型存在如此大的差异？**

现有资料还不足以回答这一点。

如果继续实板实验，最有价值的顺序应为：

1. Cfb 保持 DNP，先做 R5 A-B-A：`100Ω → 拆除 → 恢复100Ω`；
2. 如果 R5 拆除后仍然振荡，再更换一颗来源可靠的新 OPA1656，并在可行时回装原 U4 做 A-B-A；
3. 同步测 TP8 与 `TP9-TP14`，而不是分开测量；
4. 做 `0/22/47/100/220pF` 补偿梯度；
5. 尽可能捕获105 kHz从小信号到大振幅的起振过程。

现有实验记录到这里的准确结论应该是：

**105 kHz 的发生区域已经高度收敛，但唯一物理根因尚未通过实板置换或 A-B-A 实验形成最终闭环。**
