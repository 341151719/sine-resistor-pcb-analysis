# 新手先看：1SPICE_SPICE_SIM 怎么用

这个目录是主动声学阻抗 / 负阻抗电声膜项目的 SPICE 仿真包。

一句话结论：**这里用于验证“电路能否合成 1-100 ohm 等效电阻，并在 10-1000 Hz 变化下保持稳定”；当前结果是 ngspice 代理模型验证，不是最终硬件签核。**

## 1. 先看哪些文件

建议按这个顺序看：

1. `README_新手先看.md`  
   当前这份中文入口说明。

2. `PROJECT_VALIDITY_STATUS.md`  
   当前项目可信边界。这里会说明哪些结论能用、哪些不能当最终签核。

3. `docs/project_notes/SPICE完整化改进要求_2026-06-24.md`  
   后续要把 SPICE 包做到“完整”的改进清单和验收标准。

4. `docs/project_notes/SPICE_RUNTIME_TEST_REPORT.md`  
   2026-06-20 的运行测试记录，说明 smoke test 怎么跑通。

5. `docs/DYNAMIC_VALIDATION_REPORT.md` 和 `docs/FINAL_CONSOLE_SUMMARY.md`  
   早期动态验证和汇总结论。

## 2. 每个文件夹是干什么的

| 文件夹 | 用途 | 新手建议 |
|---|---|---|
| `scripts/` | 运行、检查、画图、准备模型的 Python 脚本 | 要重新仿真时用这里 |
| `spice/` | SPICE 电路、模型、官方模型包装 | 不熟悉时不要手改 |
| `results/` | 当前仿真输出 | 注意当前可能只是 smoke test 结果 |
| `docs/` | 说明、报告、模型计划、指标说明 | 查背景和结论 |
| `docs/project_notes/` | 从根目录整理下来的专项说明 | 查历史说明和完整化要求 |
| `archive/` | 历史、备份、旧日志、临时脚本、源码包 | 只看不用于当前运行 |

## 3. 最常用命令

先进入目录：

```powershell
cd C:\Users\Administrator\Documents\2SPICE\1SPICE_SPICE_SIM
```

检查项目是否完整：

```powershell
python scripts\check_project.py
```

设置 ngspice 路径：

```powershell
$env:NGSPICE_BIN="C:\Users\Administrator\Documents\Spice64\bin\ngspice_con.exe"
```

重新跑完整默认 sweep：

```powershell
python scripts\run_sweeps.py --clean
```

重新跑完整增强 sweep，包含默认 case、寄生 case、异常 case：

```powershell
python scripts\run_sweeps.py --clean --suite complete --model-lib official
```

只生成 netlist，不运行 ngspice：

```powershell
python scripts\run_sweeps.py --clean --write-only
```

只跑电注入相关 case：

```powershell
python scripts\run_sweeps.py --clean --case-filter einj
```

只跑 smoke test 时，必须输出到 `results_smoke/`，避免覆盖完整结果：

```powershell
python scripts\run_sweeps.py --clean --smoke --case-filter full_einj_fixed_r1_f1000
```

如果只需要根据现有 `results/all_summary.csv` 重新生成报告，不重跑仿真：

```powershell
python scripts\generate_completion_reports.py --results-dir results --suite complete
```

## 4. 当前结果怎么理解

当前已经有正向证据：

- `Rtarget=1 ohm` 的关键负阻抗目标在代理模型里跑通。
- `Rtarget=7.2 ohm` 的普通等效电阻点拟合非常接近。
- 历史报告记录过 34 个动态 case 全部成功。

但要注意：

- 当前 `results/all_summary.csv` 可能被 smoke test 覆盖，不一定代表完整 sweep。
- 结果里如果看到 `gmin/source stepping failed`，要继续看后面是否有 `Transient op finished successfully`。如果有，它通常只是 ngspice 初始工作点警告，不等于仿真失败。
- 当前结果不能直接替代 PCB 寄生、OPA548 热、RSH1 Kelvin 误差、供电回灌和真实扬声器台架测试。

## 5. 不要弄错的地方

- 不要把 `archive/` 当成当前运行目录。
- 不要只看 `results/all_summary.csv` 就下结论，因为它可能被单个 smoke test 覆盖。
- 不要把当前代理模型结果写成“纯厂商宏模型已经完整验证”。
- 不要把 `results/cases/*/Reff pointwise` 图当主要验收依据；主要看 `reff_fit_tail_ohm`、`synerr_norm_rms_tail`、`ilim_ratio_tail_pk`、`xmax_ratio_pk`。
- 不要随手改 `spice/models/` 里的模型文件；先复制或新建测试分支。
